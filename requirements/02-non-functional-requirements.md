# Non-Functional Requirements

"A non-functional requirement describes a system quality, operating condition or constraint. It should normally include a measurable target or a condition that can be verified. Words such as fast, secure, reliable and user-friendly are starting points for discussion, not complete requirements." ([Shields, 2026](../references/01-text-sources.md#lectures))

Each requirement below has a measurable target, or fit criterion, so that it can be shown to be met ([Robertson and Robertson, 2012](../references/01-text-sources.md#robertson); [Sommerville, 2016](../references/01-text-sources.md#sommerville)). The scenario does not state targets for performance, availability, recovery or accessibility, so these figures are temporary assumptions, linked in the table and to be confirmed with stakeholders.
